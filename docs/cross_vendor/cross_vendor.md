## 6. 8000² 的中止

1. **装载检查**（`xv_campaign.py fit`，两卡同时各一个 K = 1、一个屏障、300/100 步，不是测量）：都通过——5090 12.3 fps、XTX 5.9 fps，粒子数 64,352,484 不变，不变量全 0；5090 的显存峰值 22,618 MiB（nvidia-smi）；XTX 的显存占用读数（ADL `ADL2_Adapter_VRAMUsage_Get`）给出 46,100 MiB，超过卡的 24 GiB，不可用，没有 XTX 的显存峰值。
2. **标定通过**：第 1 轮等权重切口 803 → busy 5090 / XTX 39086 / 84621 µs → ω 1.3681 / 0.6319（切口 → 1097）；第 2 轮切口 1097 → busy 55548 / 52692 → ω **1.3445 / 0.6555**（ω_5090/ω_XTX = 2.051，切口 1079 / 1606 列，流体 43,040,000 / 20,960,000，5090 份额 67.2 %）；两轮 pilot 共 124.5 s。
3. **第 1 次试验的参考对停在构建阶段**：两个 64M 的 K = 1 进程 16:39:13 启动，各自 case_loaded 1.7 s、partition_done 9.3 s、bootstrap_start 9.7 / 12.6 s，之后主机内存接近耗尽，Claude Code 的后台内存保护把整条命令（含两个参考进程和遥测）停掉（16:39:36 之后没有新的遥测行）；日志停在 `[ChainOrchV7] N=1, 0 workers started`，没有 RESULT 行。之后查到系统空闲内存 27.6 GB / 32.6 GB，没有残留进程。装载检查时同样的两个进程跑完了 300 步，所以不是显存放不下，是两个 64M 进程同时构建时的主机内存（本机只有 1 条 32 GiB）。按规则没有重跑。8000² 因此只有标定，没有 E1 / E2 的数据。
4. 可选的处理（你定）：(a) 关掉其它占内存的程序后原样重跑 8000²（参考对仍同时启动，可能再次触发）；(b) 8000² 的两个参考改为先后各跑一次（偏离「同时、同一屏障」的协议，报告里注明）；(c) 不做 8000²，报告以 7 个尺寸为准。
