## 结论

1. **主涡偏弱里有多少来自壁面边界条件(250²):全部,而且换过了头。**
   - **主涡:** 只换壁面条件(v7 `WALL_BC = 1`,其余不动),ψ_min 从偏弱 8.64 % 变成偏强 4.33 %(−0.10866 → −0.12409;Marchi 2021 为 −0.11894),变了 13.0 个百分点。v6 K = 1 与主序列 K = 2 同为 −8.64 %。
   - **中线:** 三个极值同样从偏弱 8.2–9.3 % 变成偏强 4.4–5.2 %;相对 Marchi 的相对 L2 误差减半(u 7.25 % → 3.83 %,v 8.54 % → 4.35 %)。
   - **二次涡与涡心:** 两个底部二次涡相对 Ghia 1982 从 −18 % / −24 % 变成 +3 % / +8 %;涡心相对 Marchi 的偏差从 (+0.0027, −0.0009) 变成 (−0.0012, −0.0007)。
   - **没变的:** 内部的离散粘性算子(ν_eff / ν 0.981 → 0.980)。K = 1 与 K = 2 的 v6 在每一项上都相同(ψ_min −0.10866 / −0.10867),偏弱与分解无关。

   所以 250² 上主序列的主涡偏弱来自 v6 的壁面处理;规定的 Adami 条件把它补过了头,约 4–5 %。过冲随分辨率怎么变,要看 500²。
2. **一半来自无滑移,一半来自压力边界;密度漂移只占 0.6 个百分点。** 两个诊断模式各只换一部分(第 5 节;下面的拆分是沿"先换无滑移、再换压力"这一条路径得到的,另一种次序没跑):
   - **只把粘性项里的壁速度换成 Adami 的虚拟速度(诊断 2):** ψ_min −2.97 %,极值 −2.3 … −2.4 %,即 13.0 个百分点里的 5.7。
   - **再换成 Adami 的壁面压力(诊断 3,壁粒子存的密度固定为 ρ0、没有漂移):** +3.73 %(+6.7)。
   - **再让壁粒子存 ρ_w = EOS⁻¹(p_w)(规定的条件,有漂移):** +4.33 %(+0.6)。

   诊断 2 在 250² 上离参考最近:涡心偏差 ≤ 2 × 10⁻⁴,中线相对 L2 为 2.4 % / 3.6 %。但它的壁面压力仍是 v6 那个与流体无关的量(结论 6),这可能只是两种误差在 250² 上相互抵消,要看收敛。
3. **规定的 Adami 条件有一个规定检查项以外的问题:流体平均密度线性下降。**
   - **现象:** 粒子数守恒、不变量全为 0、runner 判 complete,但连续方程积分出的流体密度从第一步起每单位时间降 0.70–0.73 kg/m³(t = 80–100 窗口里 930–944,−6.3 %;平均压力约 −0.5 MPa)。v6、诊断 2、诊断 3 都保持在 999.99。500² 上的速率约为 250² 的一半(第 6 节)。
   - **在哪里降,和从哪里来:** 密度在全场均匀地降(声波约 0.01 个单位时间就把它抹平),所以单个时刻按接收粒子分区的预算里,内部承担约 90 %,与内部的粒子份额相当;这只说明密度在哪里降,不说明体积从哪里来。
   - **两个上角:** 我在 t ≈ 90 的检查点上核实了一点:盖的两端与侧壁相接处,流体存的速度有很大的法向分量,进左上角 0.13–0.14 U,出右上角 0.08–0.10 U(诊断 3 与规定的 Adami 都是这样;v6 与诊断 2 只有 0.04 / 0.01 U)。PST 每步把其中 75–80 % 的位移抵消,粒子并不进壁,也不离开。连续方程用的是存的速度、没有 PST 项,会把这部分并不存在的流入、流出积进密度。
   - **源的大小(复查的分析,我没有重算):** 复查用 t = 80–110 的 31 个快照把连续方程里流体与壁的通量做了时间平均,两角不平衡的净量与实测的下降速率一致。
   - **为什么 v6 没有、Adami 有(复查的受力分解,我没有重算):** v6 的壁粒子压力是 EOS(ρ0 + dt · dρ/dt),对流体与壁的相对速度起反应,把角上的流体推出去,所以没有这个源。Adami 的壁面照抄流体的压力:全场压力为负以后 TIC 一律用差式 p_j − p_i,左上角吸力区的壁面压力比旁边的流体还低,反而把流体往角里拉。
   - **诊断 3 为什么不漂:** 角上的法向速度在诊断 3 里同样存在(上面的数),所以源还在;壁粒子存 ρ0,连续方程里与壁有关的项(主要是 δ 项)把差补了回来(补偿的量是复查的估计)。规定的条件里 ρ_w 跟着流体走,没有这个参考,平均密度就一直降。
4. **存储速度的净平均通量:**
   - **大小:** v7 为 (−3.1 × 10⁻³, +8.0 × 10⁻⁴) U,v6 为 (+9 × 10⁻⁵, +3.7 × 10⁻⁴) U(t = 80–100 平均)。诊断 3 也有(−2.9 × 10⁻³),诊断 2 没有(+2.3 × 10⁻⁴),所以它来自 Adami 的壁面压力。
   - **来源:** 就是结论 3 里角上的法向速度。PST 位移的平均值把它抵消,质心不动(t = 5:平均存储速度 (−2.79, +0.67) × 10⁻³,平均 PST 位移 / dt (+3.26, −0.56) × 10⁻³)。
   - **对 ψ 的影响:** 流函数在盖那一行上的值比 v6 低 3.4 × 10⁻³,与之一致。若均匀分布,它让 v7 的 ψ_min 显得强约 1.5 %;中线极值是局部的速度值,不受这种积分偏差影响,过冲同样是 4–5 %。
5. **近壁的 u:**
   - **盖下方:** 盖那一排下方 0.25 h 处 u 从 0.908 升到 0.946,1 h 处从 0.684 升到 0.735;盖下方 Marchi 的四个参考点(y = 0.953–0.977)落在 v6 与 v7 之间。
   - **底壁上方:** 底壁那一排上方 3 h 处的回流从 −0.178 加强到 −0.207。
   - **诊断模式:** 只换无滑移的诊断 2 在盖下方就已经到了 v7 的水平(0.944)。
6. **盖角点的壁面压力在 Adami 下是合理的。** 下面的压力都相对流体平均压力、以 ρU²/2 为单位。
   - **v7:** 有流体邻居的壁粒子在左上角(上游)平均 −1.3,右上角(下游驻点)平均 +2.4,与旁边的流体同号、同量级。
   - **v6:** 壁粒子的"压力"在两个角上都在 −13 … +15 之间,与流体无关;角点流体有 −20 / +26 的尖峰,v7 降到 −5.4 / +8.4。
7. **代价:**
   - **wall pass:** 每步 57 µs,占内核时间的 14.7 %。
   - **force / density:** force 慢 21 %(每个邻居多读一次材料),density 快 11 %(壁粒子不再积分)。
   - **合计:** 每步内核时间 +21 %,fps −16 %(GPU 1 上同卡比较,2362 对 2797)。
8. **测试都过了:**
   - **复制正确:** `WALL_BC = 0` 与 v6 在 200 步上逐位相同。先要把体素表排序:v6 自己两次运行就不逐位相同(2.1)。
   - **wall pass 正确:** t ≈ 1 的 p_w、ρ_w、u_dummy 与 numpy 重算在 float32 精度内一致,有流体邻居的壁粒子两边都是 4,548 个。
   - **t = 5:** 粒子数不变,没有流体进壁区,overflow 全为 0。
   - **复查:** 4 个独立代理分别查着色器、数据流、runner 与工具、漂移机理,每条发现再交一个代理尝试推翻。代码与数据流没有发现缺陷;几处小问题已修(37e34c6),或已写进本文。

## 1. 实现(`experiment/v7`,`V7_WALL_BC`,规格常量 100 `WALL_BC`)

**WALL_BC = 0** 是现行的 v6 壁面:
- 壁粒子每步只从流体邻居积分密度(`density.comp` 跳过壁-壁对),存 ρ0,压力取 EOS(ρ0 + dt · dρ/dt)。
- force 的粘性项用壁粒子自己存的速度(0 或盖速)。

**WALL_BC = 1** 是 Adami, Hu & Adams (2012)。其余一律不动:动量方程形式、拉伸不稳定开关 TIC、PST、ξ、ε²、δ、CFL、11 层壁粒子。

- **新 pass `wall_extrapolate.comp`:** 每个 own 粒子槽一个线程,只有壁粒子做事。对支撑半径 h 内的流体邻居求和,Wendland C4,9 体素循环与距离判据都与 correction / density / force 相同。
  - 公式:
    - ũ_w = Σ u_f W / Σ W。
    - p_w = [Σ p_f W + (g − a_w) · Σ ρ_f r_wf W] / Σ W,其中 r_wf = r_w − r_f,a_w = 0,方腔里 g = 0。
    - ρ_w = EOS⁻¹(p_w),反解 Tait;底数 1 + p_w / B 下限 10⁻³,触到下限的次数计入 `wall_density_floor_count`,全程为 0。
    - u_dummy = 2 u_w − ũ_w。
    - Σ W = 0 时 p_w = 0、ρ_w = ρ0、u_dummy = u_w。
  - 写回:
    - (ρ_w, p_w) 写进壁粒子的 density_pressure 与它的 scratch。
    - (u_dummy, Σ W) 写进新的 set 0 binding 10 `wall_dummy_velocity`。它每步在 force 读之前重写,不参与 defrag、传输与重启状态。
    - 壁粒子的位置与存的速度不动:t ≈ 1 与 t = 5 的导出里,壁的速度是 0、盖是 (1, 0, 0),逐位不变。
- **位置:** density 与 scratch → primary 拷贝之后、每一个 force 之前。
  - 默认的级联 force 在 phase B 里跑,所以 wall pass 在 phase B 的 density_deep_interior 之后、force_deep_interior_scratch 之前,从 scratch 读本步流体的 ρ / p。
  - bootstrap、非级联的 phase C、单命令路径在拷贝之后从 primary 读。
  - 第 0 步之前先跑一次:bootstrap 在 correction 之前,重启在体素化之后。
- **各处的用法:**
  - density.comp:壁粒子直接返回,不再积分。
  - 流体的连续方程与 δ 项:读壁粒子存的 ρ_w(V_w = m / ρ_w,ψ = ρ_w − ρ_i)与存的给定速度。
  - force:粘性项里壁邻居用 u_dummy;压力项读 p_w 与 V_w = m / ρ_w。三种材料质量相同,force 里的 self_mass / ρ_w 就是 m_w / ρ_w。
  - KGC(correction.comp):不用改,它的 V_j = m_j / ρ_j 读到的就是 ρ_w。
- **一步滞后:** correction 与 density 在 wall pass 之前跑,读的是上一步 wall pass 写的 ρ_w。这与流体邻居自己的 V_j 是同一时间层(它们读的也是上一步 density 的 ρ),只是 ρ_w 的插值权重用的是上一步的位置。force 读的是本步的 p_w、ρ_w 与 u_dummy。复查逐条路径核对过,没有别的滞后。
- **只支持 K = 1:**
  - SphSimulatorV7 拒绝有邻居 slab 的 slab,ChainOrchestratorV7 拒绝多于一个 sim。
  - runner 的 `--solver v7` 要求 `--slabs 1`。
  - 诊断开关 `V7_FAKE_BAND_TEST` 与 `WALL_BC ≠ 0` 不能同时用(37e34c6,复查发现那条诊断路径的次序不对;本文的运行都走不到它)。
- **runner:** `experiment/validation/cavity_runner.py --solver v6|v7`,默认 v6。
  - **v6:** 环境检查、导入、meta.json、续算检查、哈希、git 记录、段记录与退出码都和以前一样,复查逐项核对过。
  - **v7(`--solver v7 --wall-bc N`):** 检查 `V7_` 前缀的发布开关加 `V7_WALL_BC`,拒绝残留的 `V6_*`;meta / 段记录多记 solver、wall_bc、下限计数与最后一个样本的流体密度;物理哈希覆盖 `experiment/v7`。

## 2. 测试

### 2.1 WALL_BC = 0 与 v6 逐位相同(200 步)

**v6 自己的 K = 1 就不能逐位重复。** 同一张卡上同样的两次运行,200 步后速度逐位相同的粒子只有 24,404 / 74,529,最大差 1.0 × 10⁻⁵ m/s。原因是体素表由原子追加建立(`initialize_voxelization.comp`、predict 的 incoming 表),表内顺序每次不同,邻居求和的顺序也就不同;E33 已在 3-D 上见过。

**测试工具里的约束(`k1_dump --canonical-lists`):** 初始体素化之后在主机上把每个体素的表按 pid 排序,并且不做 bootstrap defrag。200 步里不会遇到 defrag;其余路径与生产相同(run_pipelined depth 2、fast submit、级联 force、发布开关)。在这 200 步里,只排一次初始表就够了。

**结果:**
- 在这个约束下,v6 对 v6 逐位相同。
- v7 `WALL_BC = 0` 对 v6 在全部 10 个字段上逐位相同,74,529 个粒子。字段是:位置、速度 / 质量、ρ / p 与它的 scratch、加速度、shift、材料、KCG 逆矩阵、密度梯度 / 核和、扩展字段。
- 加了诊断模式(13e06e5)之后重做:`WALL_BC = 0` 对 v6、`WALL_BC = 1` 对主运行那一版,都逐位相同。
- 复查另外核对了 SPIR-V:除 density 与 force 外,其余着色器反汇编后与 v6 只差 id 编号。

### 2.2 t ≈ 1 的壁面量与 numpy 重算(float32 精度)

v7 `WALL_BC = 1` 跑到第 33,333 步(t = 0.99999)。上一次 defrag 在第 33,000 步,之后不再 defrag,导出的就是最后一次 wall pass 的输入与输出。用 float64 numpy 从同一批粒子重算(`check_wall_pass`),结果如下。下面的 ε 是 float32 机器 ε;p_w 的误差以 Σ|p_f| W / Σ W 为尺度,u_dummy 以 max(|ũ|, U) 为尺度。

- **有流体邻居的壁粒子:** numpy 与 GPU 都是 4,548 个(壁 3,304、盖 1,244,全部壁粒子 11,528),一个不差。每个有 1–38 个流体邻居,中位数 16。
- **主体(Σ W ≥ 10⁻³ W(0) 的 4,048 个):** p_w 误差 ≤ 4.0 ε,ρ_w ≤ 0.76 ε,u_dummy ≤ 3.0 ε,Σ W ≤ 23 ε。
- **全部 4,548 个:** p_w ≤ 10.2 ε,u_dummy ≤ 19.3 ε,Σ W 的相对误差最大 2.8 × 10⁻³。差别集中在只有支撑边缘上一两个流体邻居的壁粒子上:q → 1 时 (1 − q)⁶ 把 float32 位置差的舍入放大,而这些权重本身极小,不是错误。
- **没有流体邻居的壁粒子:** 精确等于 (ρ0, 0, u_w);下限一次也没触到。
- **没测到的部分:** 重力项 (g − a_w) · Σ ρ_f r_wf W 在方腔里乘以 g = 0,这个测试没有检验它的符号;有重力的算例要另测。

### 2.3 250² 跑到 t = 5

v7 `WALL_BC = 1` 跑 166,667 步,每 1000 步在 defrag 边界排空之后检查一次:
- 存活粒子始终 74,529,overflow 计数全为 0,KCG 回退 0,EOS⁻¹ 下限 0。
- 越过有效壁面的流体粒子 0 个。有效壁面定义为 max(|x|, |y|) > 0.5 + dx / 2 = 0.502:流体格点到 ±0.5,最内一排壁粒子在 ±0.504。采样到的最远位置是 0.5009。

**新 pass 的耗时占比。** 在 GPU 1 上各跑 21,000 步,取每个 defrag 之前最后一帧的 GPU 时间戳,19 帧的中位数:

| 配置(GPU1,21 000 步,最后一帧 GPU 时间戳中位数) | 每步内核 µs | 壁面 pass µs(占比) | force µs | density µs | fps |
|---|---|---|---|---|---|
| v6 K=1 | 323.1 | 0.0(0.0 %) | 96.3 | 110.6 | 2797 |
| v7 K=1 WALL_BC=0 | 323.1 | 0.0(0.0 %) | 96.3 | 110.6 | 2812 |
| v7 K=1 WALL_BC=1 (Adami) | 389.4 | 57.3(14.7 %) | 116.7 | 98.3 | 2362 |

**t = 5 的测试同时暴露了一个规定检查项以外的问题。** 流体的平均密度线性下降,每单位时间 −0.73 kg/m³:t = 1 时 999.31,t = 5 时 996.39,平均压力 −36 kPa;同期 v6 为 999.998。粒子数守恒、没有流体进入壁区:漂的是连续方程积分出的密度,不是粒子丢失。原因见结论 3 与第 5 节。

- **三组结果:**
  - **GPU 0,v7 `WALL_BC = 1`,K = 1**(`logs/e36/runs/n250_k1_v7_adami`):t = 90.72 才判稳(t = 70.56 与 80.64 两个窗口的剖面变化为 1.05 与 1.25 × 10⁻³,略高于 10⁻³ 的门槛),跑到 t = 110.73,用时 27 分钟。
  - **GPU 1,v6,K = 1,同一算例、同一设置**(`logs/e36/runs/n250_k1_v6`):t = 70.56 判稳(与主序列 K = 2 相同),跑到 t = 100.02,用时 20 分钟。
  - **主序列 K = 2**(已有,`logs/validation/cavity_re1000/n250_k2_float32_xi0p001_eps0p0025`):在 9cde618 加未提交改动上跑的;与 K = 1 基线的代码版本不同,但两者在每一项上都相同。

**500²(按关卡)。** 两个运行从 21:01 起同时在跑,用主序列 500² 的算例(`cases/lid_driven_cavity_2d_n500_xi0p001_eps0p0025`,273,529 个粒子,dt = 1.5 × 10⁻⁵),设置与 250² 相同:

**1000²:** 等你批准。

**漂移怎么处理(要你定)。** 规定的 Adami 条件按原样用作生产边界不行:平均密度每单位时间降 0.07 %(250²)。几种做法:
- **(a) 用诊断 3:** 壁面存 ρ0,压力与无滑移按 Adami。不漂,主涡与规定的条件只差 0.6 个百分点;但连续方程 / δ 项 / KGC 见到的壁面密度不再是 Adami 的 ρ_w,角上的源还在,只是由 δ 项补偿。
- **(b) 只换无滑移(诊断 2):** 250² 上离参考最近,没有漂移、没有净通量;壁面压力与角点尖峰与 v6 相同。是否只是误差相抵,要看 500² / 1000² 的收敛,这需要再跑诊断 2 的 500²。
- **(c) 从源头修:** 角上存储速度的法向分量与 PST 的抵消。可以把 PST 位移写进连续方程(δ⁺-SPH 的 ALE 项),或者专门处理盖与侧壁相接的两个角。这会动到内部格式,超出"只换边界"。
