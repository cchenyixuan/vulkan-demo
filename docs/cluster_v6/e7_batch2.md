### 4.3 传输链的三跳拆分（第四次补测第 4 项，只用现有 trace）

沿用 E29 的 trace 模型（`experiment/v7/analysis/step_trace_model`，稳态步 = step ≥ warmup，GPU 时间换到主机时钟），每条链路每个稳态步拆成三跳，三跳逐步相加正好等于 t_chain：

- **readback**：发送端结束 → readback 结束（发送端 GPU：队列起步 + DMA + 屏障）；
- **主机段**：readback 结束 → 主机拷贝完成，扣掉接收端的两次等待（worker 看到 readback、帧戳检查、memcpy）；
- **upload**：拷贝完成 → upload 结束（主机信号、队列起步、DMA，接收端 GPU）。

**主机段 memcpy 的实现**（读 rc2 c56d078 的代码，没有改动）：

- 不是 `ctypes.memmove`，也不是 `np.copyto`，而是 numpy 的切片赋值：`transport_v7.py` 的 `GhostMigrationWorker._run` 第 2 步按段循环、只拷有效部分（`V7_WORKER_COUNT_AWARE=1`，默认开）；每段先用 `struct.unpack_from` 从源缓冲读出有效粒子数，再 `self._dest_view[a:a+n] = self._source_view[a:a+n]`。两个视图都是 `np.frombuffer(vkMapMemory(...), dtype=np.uint8)`，即常驻映射的主机可见缓冲（`simulator_v7.py` 约 1581–1590 行）。
- 集群上是 numpy 2.5.3。对照 v2.5.3 的源码：切片赋值走 `PyArray_CopyObject` → `PyArray_AssignArray` → `raw_array_assign_array`，后者在不需要 Python API 时（uint8 到 uint8 不需要）调用 `NPY_BEGIN_THREADS_THRESHOLDED(nitems)`，这个宏只在 nitems > 500 时释放 GIL：大于 500 字节的段在拷贝期间释放 GIL，不超过 500 字节的段持着 GIL 拷。
- 每步每条链路 14 段（ghost_layers = 2、packed_replicas = 1、lean_transport = 1、compact_ghost_lists = 1）：4 个打包的副本块、4 个迁移粒子字段、2 个 ghost 体素表、3 个计数字、1 个帧戳。4 个 4 字节的字总是持着 GIL 拷；迁移段要看当步的粒子数；段与段之间的 Python 代码（`struct.unpack_from`、切片）持着 GIL。trace 里的 memcpy 区间（worker_stamp → worker_copy）覆盖整个这个循环；这批运行 `V7_POOL_PEAKS=0`，循环前的计数读取为空。
- Python 3.13.15 标准版，带 GIL（`Py_GIL_DISABLED=0`），线程切换间隔 0.2 ms（run_meta 的 `switch_interval_s=0.0002`）。每条链路一个 worker 线程，共 2(K−1) 个，和主提交线程在同一进程、共用一个 GIL；每个 worker 绑在接收端 GPU 所在 NUMA 节点的 CPU 上。
