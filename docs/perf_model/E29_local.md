## 结论

1. **传输链本身符合模型。** 去掉"等接收方"的两段之后,传输链 t_chain = τ0 + B_host / β:**τ0 = 122.3 µs、β = 3.76 GB/s**,18 条链路(B_host 39 KiB – 11.8 MiB)相对残差 rms 4.9 %、最大 9.7 %。分三跳(边界在 readback 结束与 memcpy 结束):readback 48.3 µs + DMA 字节 / 28.3 GB/s;host(worker 醒来、帧戳检查、memcpy)31.8 µs + 主机字节 / 7.33 GB/s;upload(主机 signal、队列启动、DMA)37.0 µs + DMA 字节 / 15.8 GB/s。
2. **按任务定义的 t_tr 含两卡的相位差,不能拿来拟合。** t_tr 从发送方 ghost_send 结束算起;worker 拷贝前要等接收方自己的 readback_done(n)(时间线守卫),所以接收方落后时 t_tr ≈ 相位差:2-D 16M 一条链路 t_tr p50 12.7 ms(T_B 12.8 ms),另一条 0.5 ms。用 t_tr 拟合得 τ0 = 407 µs、β = 0.79 GB/s,相对残差 rms 214 %。N ≥ 1M 时逐步较差链路的 r = t_tr / T_B 的 p50 是 0.45–1.00,其中传输链本身(r_chain)只占 4–36 %,其余是相位差;10k–250k 时 r_chain 占 r 的 52–77 %。所以下面另给 r_chain = t_chain / T_B 与 r' = (upload 结束 − 接收方 B 开始) / T_B(> 1 即暴露)。
3. **c_B 与 r_pred。** c_B(K = 1 的 T_B 对 N,过原点)2-D 1.611 ns / 粒子、3-D 8.133 ns / 粒子。2-D 在 N ≥ 1M 时各卡 K = 1 的 T_B / N 是 1.59–1.68 ns(每个算例两卡平均 1.61–1.66),K = 2 的 T_B 与 c_B · n_B 差 −0.5 … +8.7 %;3-D −1.6 … +9.7 %。3-D narrow 的偏差(+8.7 / +9.7 %)来自模型只数 force sweep:phase B 的 correction 与 density 在 band 2 之外,只有 force 在 band 3 之外(= n_B);按本算例 K = 1 的 phase B 分两部分各乘对应的粒子数,narrow 变成 −1.9 / +0.1 %,3-D 1M 与 2-D 1M 仍是 +6.4 / +10.7 % 与 +7.7 / +7.9 %。**N ≥ 1M 的 6 个算例(每个算例取较差链路)r_pred(t_chain) 与实测 r_chain p50 差 −7.2 … +12.1 %**(2-D 1M / 4M / 16M:0.259 对 0.231、0.090 对 0.089、0.036 对 0.039;3-D 1M / narrow / 8M:0.206 对 0.193、0.257 对 0.231、0.093 对 0.096);逐条链路比是 −6.5 … +15.5 %。闭式近似与 r_pred 差 −0.7 … −5.7 %(较差链路;逐条链路 −0.7 … −6.9 %)。r_pred 用的是 t_chain 的常数;按任务定义用 t_tr 的常数算出的 r_pred(t_tr) 也列在表里,它把相位差当成传输,N ≥ 1M 时与 r 差得很远(2-D 16M 0.16 对 0.97)。**小 N 失效**:phase B 被派发开销主导(2-D 10k 的 K = 1 T_B 252–253 µs,K = 2 每卡 247–249 µs,不随粒子数减半),c_B · n_B 只有 8–10 µs,r_pred = 16 对实测 0.595;改用该算例自己 K = 1 的 c_B 也只到 1.54 对 0.595。
4. **η 为什么在 r < 1 时就掉。** r_chain 的 p50 全部 < 1(0.04–0.60)、p95 ≤ 1.03:传输链本身基本藏得住。η 的损失来自 K = 2 每步比"K = 1 的一半"多出来的时间(见"每步时间构成")和两卡不同相。η 都是单次试验(见 η 表;同一算例开 / 关两次在 3-D 差到 2.3 个百分点)。
   - **2-D:多出来的是藏不进 phase B 的固定工作。** phase C 每步多 153–286 µs(K = 2 的 C 是 band、install、展开、departed 等一串小派发:10k–1M 是 211–233 µs,K = 1 只有 4–39 µs)、phase A 多 21–117 µs(ghost_send)、C → 下一步 A 的间隙多 35–43 µs(K = 2 37–46 µs,K = 1 5–6 µs);小 N 时 phase B 也不减半(多 56–126 µs)。C → A 间隙在 GPU / 驱动一侧:主机在 C(n) 结束之前至少 445 µs(95 % 的步)就已提交了第 n + 1 步,而 K = 1 的循环结构相同却只有 5–6 µs;`simulator_v6.py` 的注释把它记为 GPU 调度晚评估 phase A 对 frame_done(n − 1) 的等待(`V6_PHASE_A_NO_WAIT`),这里没有测。10k 的 K = 2 一步约 556–558 µs(中位数),是 K = 1 一半的 3.9 倍,η = 24 %;1M 多约 330–350 µs,η = 71 %;4M、16M 多出的时间相对 T_B 已小,η = 93–95 %。
   - **3-D:phase C 很重。** 每步 2.9 ms(1M,w = 15–16)、5.8–5.9 ms(narrow,w = 12–14)、6.3–6.4 ms(8M,w = 27–29),K = 1 只有 0.06–0.36 ms;C / B = 0.49–0.50、0.37–0.45、0.17。B 比 K = 1 的一半短 0.5–6.0 ms(band 粒子挪到了 C),相抵之后仍多出。
   - **slab 负载不均(3-D narrow、8M)让快的一边每步干等。** weights 1,1 分出的两个 slab 在 3-D narrow 的 n_B 差 21 %(1.48M 对 1.79M)、3-D 8M 差 7.5 %、3-D 1M 6.6 %;narrow 与 8M 里较快的 s0 每步在 B 与 C 之间等 s1 的数据(中位 3.06 ms、1.73 ms)。这在 r' 上是"暴露"(98.7 % / 69.7 % 的步),但不是传输(r_chain p95 0.26 / 0.12)。2-D 除 10k(21 %)外 n_B 差 0.45–6.0 %。
   - **两卡不同相。** depth 2 下一张卡可以领先另一张直到约 T_B − t_chain 而不必等,再多就在 B 与 C 之间等。逐步的 |Δ'| / T_B 中位数:2-D 10k 0.12–0.13,2-D 62k–4M 0.28–0.39,3-D 1M 0.56,2-D 16M、3-D narrow、3-D 8M 0.82–1.00。2-D 10k、1M、4M 领先的一方逐步交替(2-D 1M 每条链路 2000 步里换号 56–58 次,Δ' 落在 ±0.1 T_B 之外的两侧各占 41–43 %),有符号的中位数接近 0,但两卡典型相差 0.38 T_B。哪张卡领先,在 2-D 里与 n_B 不均无关:2-D 16M 里领先并等待的是 n_B 较大、T_B 中位数较长的 s1(13,047 对 12,845 µs);只有 3-D narrow 与 8M 是"较快的 s0 领先并等待"。旧的 r 假设两卡同时进入 phase B,把相位差混进了传输。2-D 16M 的中位数上没有等待,但 38.6 % 的步在等(平均到每一步 455 µs,等待的那些步平均 1.18 ms);开仪器那次运行的周期是 15.02 ms(66.58 fps),设备上的平均周期 14.95 ms(两卡),比各自的中位数 14.39 / 14.53 ms 长 0.57 / 0.42 ms:s1 的超出大部分来自 B → C 的等待(平均 478 µs),s0 的超出来自它自己 T_B 的尾部(p95 14,702 对 p50 12,845 µs)。
5. **host 步(补完 E24)。** 2-D 1M 每条链路:memcpy 45 µs(p95 89 µs,7.3 GB/s)、帧戳检查 1.1–1.3 µs、signal(两次主机 signal 都返回)13.5–13.8 µs、等接收方上一步 upload 5 µs、等接收方 readback_done 26–36 µs(p95 643–657 µs);"等发送方 readback"1.08–1.12 ms 是 worker 提前取到帧号、在等 GPU,不在关键路径上。主机拷贝 7.0–7.35 GB/s(2-D 1M、16M、3-D 8M)。落后接收方那条链路的"等接收方 readback_done"就是相位差(16M 12.2 ms、3-D 8M 35.0 ms)。修正后的仪器把 signal 拆开(2-D 1M 验证运行):拷贝结束 → 给接收方 signal 之前(先给发送方 consumed signal、查一次信号量)p50 7.5–7.7 µs,之后到 upload 开始(signal 调用本身与 upload 队列启动)25.6–28.9 µs。

## 记录字段(E7 沿用)

开关:`experiment/v6/_run_v6_chain_bench.py --step-trace DIR`(默认关;关时录制与提交的 GPU 命令和以前完全相同),`--step-trace-detail phases|full`(默认 phases:各 phase 的开始与最后一个 tick、两个 ghost_send 的结束、全部传输 tick;full 另加 phase 内每个 kernel 的 tick),`--step-trace-calibrate-ms`(默认 500)。只能用 depth ≤ 2,不能与 `--anatomy` / `--phase-trace` 同开,`V6_PER_SIM_PIPELINE=1` 时拒绝(0 与 2 可以)。实现:`experiment/v6/utils/phase_trace_v6.py` 的 `StepTracer` / `StepTraceTimer`,时钟映射在 `experiment/v6/utils/clock_map_v6.py`(只依赖 numpy,分析脚本也用);共享文件只改了 `simulator_v6.py`(按帧奇偶各录一份 phase A/B 与传输命令,只在 trace 打开时)和 `transport_v6.py`(worker 的主机时钟可替换、帧戳检查之后与给接收方 signal 之前各多一个时间点、每步拷贝字节)。每次运行一个目录,四个文件;时间一律是**主机时钟上的 ns**(整数)。

**时间基准。** GPU 时间戳经 `VK_KHR_calibrated_timestamps` 映射到主机时钟:一个辅助线程每 500 ms 采一次(每次连采 3 对、取驱动 maxDeviation 最小的一对;驱动调用不占主循环),开头、warmup 边界(流水线排空时)和结尾各采 5 / 3 / 5 次(每次 8 对)。设备 tick 保持整数,减去每卡的整数原点(第一次标定的 tick)之后才转浮点。每台设备的映射(`clock_map_v6.fit_clock`)只用 maxDeviation 不超过本次最小值 + 1 µs 的对(更宽的对,主机读数最多偏晚它的宽度),= 最小二乘直线 + 直线残差的 9 点滑动中位数(按设备时间线性插值),再剔除离"直线 + 中位数"超过 3σ 的对、重拟合到稳定;同一设备的 compute 与 transfer 两个计时池共用这一映射。需要中位数一项是因为两种钟的频率比在几分钟里会漂几个 ppm:检查运行 3-D 8M(140 s)单用直线时残差 rms 7.6 / 5.5 µs,中位数一项本身跨 −18.4 … +9.2 µs(GPU 0)与 −12.4 … +6.9 µs(GPU 1),加上后残差 rms 56 / 79 ns、最大 259 / 493 ns。驱动报的 maxDeviation 最小约 12 µs:每一对标定样本的两个读数之间就有这么宽的窗口,所以 GPU 与主机之间的**绝对**对齐只能保证到这个量级;映射残差(下面检查里的容差)衡量的是映射本身的一致性。主机时钟 = worker 时间点用的钟:Windows 是 QPC(`time.perf_counter_ns`,本机 QPC 10 MHz,与 perf_counter_ns 一致到 100 ns 一格);Linux 优先 CLOCK_MONOTONIC_RAW(不受 NTP 调速,tracer 与 worker 都改用 `time.clock_gettime_ns(CLOCK_MONOTONIC_RAW)`),驱动不给时用 CLOCK_MONOTONIC(`perf_counter_ns`)——**Linux 两条路径都没测**,E30 的 S1 会报集群上的时间域。

**时间戳为什么每步都在。** 每个按帧的标签在计时池里有两个槽(偶数帧一块、奇数帧一块),第 n 步的 phase A 第一件事是复位本奇偶的块(compute 池直接复位;transfer 池由 phase A 在 compute 队列上复位——transfer 队列不能复位查询池)。第 n 步的块要到第 n + 2 步的 phase A 才会被复位,而 depth-2 主循环在读完第 n 步之后才提交第 n + 2 步;第 n − 2 步的 readback / upload 也一定在第 n 步的 phase A 之前完成(phase A(n) 等 frame_done(n − 1),后者经 upload_done → worker → 本卡 readback_done(n − 1) 排在本卡 readback(n − 1) 之后)。所以只能用 depth ≤ 2(bench 会拒绝 depth 3)。跨队列的顺序靠的是 COMPUTE_SHADER / ALL_TRANSFER 阶段上的信号量等待,规范并不保证它覆盖查询池复位与 BOTTOM_OF_PIPE 时间戳;本机驱动上成立(59 次带仪器的运行里没有一个不可用的 tick),换驱动要先查 `missing_ticks`。

### 派生量(`experiment/v6/analysis/step_trace_model.py`)

- t_tr = `upload_end − send_end`,拆成首尾相接、互不重叠的 11 段:readback 启动(`send_end → readback_start`)、readback DMA、屏障、readback 结束 → worker 看到(`readback_end → worker_source_wait`)、等接收方 readback_done、等接收方上一步 upload、帧戳检查、memcpy、signal(`worker_copy → worker_dest_signal`)、signal → upload 开始、upload DMA。没有 `worker_dest_signal` 的旧数据把最后两段之前的两段合成"拷贝结束 → upload 开始",共 10 段。按任务的五段合并:readback = 前三段;readback 结束 → worker 看到;host 段 = 两段等待 + 帧戳 + memcpy;拷贝结束 → upload 开始;upload DMA。
- t_chain = t_tr − 两段等接收方;链的三跳:readback(`send_end → readback_end`)、host(`readback_end → worker_copy` 减两段等待)、upload(`worker_copy → upload_end`)。
- host 步(worker,补完 E24):等发送方 readback(`dequeue → source_wait`,与 GPU 段重叠,不在 t_tr 的关键路径上)、等接收方 readback_done、等接收方上一步 upload、帧戳检查、memcpy、signal(`worker_copy → worker_signal`)。
- T_B = 接收方 `b_end − b_start`;r = t_tr / T_B、r_chain = t_chain / T_B、r' = (`upload_end` − 接收方 `b_start`) / T_B,逐步取较差的链路。
- 相位差 Δ' = 接收方 `b_start` − 发送方 `send_end`,逐步的 Δ' / T_B 与 |Δ'| / T_B。
- 暴露时间 = max(0, `upload_end` − 接收方 `b_end`);C 前总等待 = 接收方 `c_start − b_end`。
- C → A 间隙 = 每 sim 的 `a_start(n) − c_end(n − 1)`(GPU 上的空闲)。

## 第二段:本地扫描与模型

**做法。** 9 个算例:2-D 10k(`logs/two_hop_experiment/cases/cavity_2d_10k`,每 slab 12 / 14 列;注意它的 ξ = 0.1,与其余 2-D 算例的 ξ = 0.001 不同)、62k、250k(用 1M 的生成器与参数新生成,见下)、1M(`lid_driven_cavity_2d_gen`)、4M、16M;3-D 1M、narrow(每 slab 12 / 14 列)、8M。每个算例依次:K = 1 在 GPU 0 与 GPU 1 上同时各一个进程、K = 2(GPU 0,1),都不开仪器(η 用这两次的 fps);再同样两次都开仪器(分解;K = 1 的 T_B 给 c_B)。按任务要求各一次,不做多次试验,所以 η 是**单次**的值:同一算例开 / 关仪器各算一次 η,在 2-D 差 ≤ 0.4 个百分点、在 3-D 差到 2.3 个百分点(差来自 K = 1 参照,不是 K = 2),按你定的效率规则(≥ 3 次交替试验、带误差棒、同时报 η_min)这些只能当示意。η = fps_K2 / (2 · mean(fps_K1,GPU 0, fps_K1,GPU 1)),η_min = fps_K2 / (2 · min(…));GPU 0 带桌面,K = 1 时比 GPU 1 慢 1.5–4.8 %(3-D 8M 例外)。运行中没有采 SM 时钟与功率,只在每次运行前记了一次。

## 对 E7 的建议

**必须记的字段。** 上面的规格整套照用(`--step-trace DIR`,默认的 `phases` 细度,修正后的版本):每步每 sim 的 phase A/B/C 起止与两个 ghost_send 的结束;每步每条有向链路的 readback / upload DMA 起止、worker 的 8 个时间点(含 `worker_dest_signal`)、主机拷贝字节与 DMA 字节;`run_meta.json` 里的 w、band、n_B(warmup 边界从 voxel 计数读)、映射参数与残差、驱动 maxDeviation。只记 t_tr 不够:要把落后的接收方造成的等待(`worker_dest_guard − worker_source_wait`)与传输链本身分开,并且要有接收方的 b_start / b_end 才能算暴露(r')。K = 8 的链上每条链路都有自己的相位差,逐条链路记录(工具已经这样做)。

**η 与分解分开跑,η 要多次。** 仪器在 1M 量级的步长上要 1.1–1.5 %(本机),所以 η 用不开仪器的运行,分解与 r 用开仪器的运行。η 每个点至少 3 次交替试验(K = 1 参照两卡同时、K = 2,按 probe34 的做法轮换),报平均 ± 标准差与 η_min,运行中采每卡的 SM 时钟与功率(本机同一算例两次之间 η 差到 2.3 个百分点,来自 K = 1 参照);带仪器的分解每点一次即可。分析脚本按记录里的 `trial` 字段分组算 η。

**时钟。** 集群是 Linux:tracer 优先 CLOCK_MONOTONIC_RAW(同时把 worker 的主机钟换掉),否则 CLOCK_MONOTONIC;这两条路径都没测,先看 E30 S1 报的时间域,并在第一批运行里检查 `run_meta.json` 的映射残差、用到的标定对数与驱动 maxDeviation,以及 `missing_ticks`。运行长于几十秒时直线映射不够(本机 140 s 里中位数一项跨约 −18 … +9 µs),已经用滑动中位数修正;集群上要确认同样有效。

**C → A 间隙要单独查。** K = 2 每步 37–58 µs、K = 1 5–6 µs,在 2-D 小 N 是 η 损失的一部分;它在 GPU / 驱动一侧,建议在集群上加一组 `V6_PHASE_A_NO_WAIT=1` 的对照(只做诊断,不改默认)。

**算例矩阵要覆盖两个区。** 本机看到两个区。(一)每步固定成本与传输区:2-D 总 N ≲ 1M(每卡 n_B ≲ 0.5M,T_B ≲ 0.9 ms),K = 2 每步多出的固定工作约 0.3 ms(phase C ≈ 0.21 ms、ghost_send、C → A 间隙)与传输链 t_chain ≈ 0.14–0.2 ms 都与 T_B 同量级,η 24–71 %;(二)计算区:2-D 总 N ≳ 4M(每卡 n_B ≳ 2M)、3-D 宽 slab,r_chain ≤ 0.1,η 由 phase C / A 的附加工作、slab 负载差与相位差决定。集群上两区都要有点,按每卡的粒子数:2-D 每卡 n_B ≈ 32k / 130k / 0.5M / 2M / 8M(即本机 62k / 250k / 1M / 4M / 16M 算例在 K = 2 时的每卡量;K 更大时总 N 按 K 放大),3-D 每卡 n_B ≈ 0.7M / 4.7M(本机 3-D 1M / 8M),再留一个窄 slab(本机 narrow:每卡 1.5–1.8M,w − b ≈ 9–11,r_chain 0.23);K = 2、4、8。K ≥ 3 的中间 slab 有两条 seam:phase C 的 band 与 ghost_send 加倍,n_B 两侧都扣 band,两条入站链路各有相位差,要单独看。用 r_chain(而不是 t_tr / T_B)和 r' 判断传输是否藏住,用每步时间构成(A、B、B→C、C、C → A 间隙)解释 η。

**同时记录的协变量。** 每卡的 SM 时钟与功率(运行中采样)、每 slab 的 own 粒子数与列数(负载差决定 3-D 里谁等谁;2-D 里谁领先与负载无关,要靠逐步的 Δ' 看)。

**空闲检查。** 本地 campaign 的检查只在每次运行之前做、看不到运行当中另一会话起的进程;集群节点独占时不需要,本机上照旧。
